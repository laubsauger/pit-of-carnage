# Decisions

Decisions that shape the game and the code, newest first. Add a row when a decision is made or
reversed. A reversal gets its own row; never edit an old row.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-10-15 | Docs describe decisions and the current state: `SPEC.md` (behaviour), `ARCHITECTURE.md` (code), `DECISIONS.md` (this log), `STATUS.md` (rewritten each pass). The append-only build spec is retired. | The build spec grew by appended "must fix" and "user feedback" sections and stopped reading as one current spec. |
| 2026-10-15 | Screen shake only on kills: one short decaying shake per kill, capped. Ordinary hits get local weight (hit-stop on the two fighters, flash, squash, knockback slide, impact ring, HP chip). | Shake on every hit and projectile impact turned into constant rumbling and hid who hit whom. |
| 2026-10-15 | Carnage is the default blood setting (`DEFAULT_VIEW_SETTINGS.blood = 'carnage'`). | User: vicious, comic splatter out of the box is the point of the game. Light and normal stay available. |
| 2026-10-15 | Fog of war for the selected fighter is on by default. | Seeing the pit through one fighter's eyes is how a viewer understands its decisions. |
| 2026-10-15 | Hearing is fuzzy, and a fighter that loses sight of a target loses the target: it keeps only the last seen spot, then searches. | Pass 1 fighters looked omniscient: 360° hearing through walls wrote exact live positions into memory, so anyone in a fight was tracked perfectly behind walls. |
| 2026-10-15 | No three.js shadow maps. Light comes from a TSL compute light field with 2D wall and pillar occlusion that matches the sim's `lightAt`; fighters, weapons, projectiles and gibs cast soft projected quads, one per nearby light. | What players see as shadow must match the sim's shadow rule (stealth depends on it). Projected quads give soft per-light shadows for 16 moving bodies at low cost. |
| 2026-10-15 | Sudden death is a closing wall with a stalemate trigger (15 s without damage), escalation and a hard cap with a judges' decision. | Hiding or getting stuck must never stall a match; every match ends, and a judged ending is announced and reported, never silent. |
| 2026-10-15 | Balance is measured by a harness (`npm run balance`, `docs/BALANCE.md`), not guessed. | The starting table from the samples favoured ranged weapons; only many seeded matches show whether a change helps. |
| 2026-10-15 | Multiplayer uses host-authoritative WebRTC rooms: the host simulates and streams state, peers watch. A small peer-to-peer prototype (Trystero, no backend) comes before any server work. | Lockstep needs identical results on every machine, but `Math.sin` and other float functions can differ between browsers, so a lockstep sim would drift. The prototype answers whether multiplayer is worth more time before anyone builds a server. |
| 2026-10-15 | Evolution uses MAP-Elites style niches (weapon family x preferred range x aggression) with paired seeds and a re-test before a title changes hands. | A single "best so far" converges on one archetype and crowns a new champion every generation by luck. Niches keep the meta open. |
| 2026-10-15 | Ratings come from openskill (Plackett-Luce over FFA placements), updated from every rated match and persisted. Never set by hand. | The samples' ratings plateaued at 1253 because they were set by hand; a real rating system must move with results. |
| 2026-10-15 | Sound is procedural: synthesized with WebAudio at runtime, no audio asset files. | No licensing or download weight, and every cue can vary in pitch and texture so repeats do not sound canned. |
| 2026-10-15 | One gate for strategies: `loadStrategy(input, source)` for every source, returning a branded `ValidStrategy`; only that type compiles into a brain. | Imported files, pasted text, codes, saved versions, house stacks, evolution children and later network peers must all meet the same rules; the type system makes skipping the gate a compile error. |
| 2026-10-15 | The expression language is parsed once into an AST and evaluated by a small interpreter. No `eval`, no `Function`, no loops or recursion. | Strategies come from strangers and LLMs. Without eval they cannot run code; without loops they cannot hang; their cost per think can be computed before the match. |
| 2026-10-15 | One registry (`src/brain/registry.ts`) defines every sensor, place, zone, move term and policy with doc, unit and range. The validator vocabulary, the JSON Schema and the LLM rulebook are generated from it. | Three hand-kept copies would disagree. With one source, the editor, the validator and the LLM all describe the same language. |
| 2026-10-15 | Strategies are behaviours composed from documented primitives (scored behaviours, context-steering move terms, attack and skill policies), not named black-box verbs. | Players and LLMs can invent tactics the designers did not foresee, and the inspector can show exactly why a fighter did something. |
| 2026-10-15 | three.js r186 with `WebGPURenderer` only, TSL node materials and a TSL `RenderPipeline`. No WebGL fallback anywhere. Without WebGPU the arena shows a "WebGPU required" message; the Gym and Room still work. | User: future-proof and less code. One render path means no second set of shaders, no fallback branches and no WebGL-only APIs. |
| 2026-10-15 | React 18 for the UI shell only. The app loop owns the frame; React reads a controller snapshot at about 10 Hz. | React re-rendering in the per-frame path would cost frames with 16 fighters on screen. |
| 2026-10-15 | A Vite + strict TypeScript project that builds to one static page (deployed to GitHub Pages), instead of a hand-edited single HTML file. | The samples were single hand-edited HTML files with broken, unwired systems. Modules, types and tests let parallel builders work safely; the output is still a static page that needs no server. |
| 2026-10-15 | Free-for-all is the default format: 8 fighters on the pit. Squads and duels are options. | The core fantasy is a chaotic brawl where any strategy can win; FFA also gives ratings many placements per match. |
| 2026-10-15 | Deterministic simulation: the sim, brains and strategy code draw randomness only from the seeded, forkable `Rng`. Same config and seed give the same match in the same browser. | Replays, seeking, gym reports and "Watch this match" all rebuild matches from config and seed instead of storing them. |
| 2026-10-15 | The sample prototypes in `docs/sample/` are concept references only. Their code and structure are never ported. | Many of their systems are broken or fake (evolution and ratings do not work, several controls are unwired). Take ideas, build each system properly. |
