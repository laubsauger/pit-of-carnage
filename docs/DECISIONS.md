# Decisions

Decisions that shape the game and the code, newest first. Add a row when a decision is made or
reversed. A reversal gets its own row; never edit an old row.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-10-16 | Watch-screen panels keep floating over the canvas and reporting view insets (confirms the 2026-10-15 row). | The user kept working with the floating panels through pass 3 without objecting, so the pending reading of the spec stands. |
| 2026-10-16 | Automated browser checks open the app with `?mute`, which never creates an AudioContext, and run under the GPU lock (`scripts/gpu-lock.mjs`), one short session at a time. | Agents' checks played sound on the user's machine and competed for a shared GPU. Sound is checked offline through the real `SoundDriver` instead. |
| 2026-10-16 | Arrows and thrown axes stick where they hit (walls, props, bodies) and are taken back from there; ammo in a living body is out of play until it dies. Throwing axes keep a hatchet and the staff whacks up close (`WeaponRule.handDamage`); the bow's quiver refills one arrow every 240 ticks. | Stuck ammo makes ammo an economy you can see. Without a hand weapon, axes threw their axes into whoever closed in and then punched for 6, losing nearly every melee duel; with every hit arrow stuck in a body the bow ran dry. |
| 2026-10-16 | The shrine recharges in 900 ticks (was 320). | The biggest FFA lever the harness found: with a heal every 5 s shrine squatters and slow melee won the pit; 900 brought both families inside the target band. |
| 2026-10-16 | Bleed is built behind `BLEED_RULES.enabled` and ships off: no bleed, no sensors, nothing in the rulebook or Codex while it is off. | The harness never measured it; the spec adopts bleed only if it adds variety without dominating. Building it behind one switch keeps that decision cheap. |
| 2026-10-16 | Two new skills, HOOK and SECOND_WIND, go everywhere skills are listed (rules, sim, registry, rulebook, Codex, builder, renderer, audio, house stacks). | Strategies needed more ways to express a plan (pull a target off a perch, recover mid-fight); measured against DASH, neither dominates. |
| 2026-10-16 | The victory moment is driven by two app signals, `victory` (once per match decided live) and `end_card` (whenever the card comes or goes, seeks included); a room's stream sends its own. | Like the other round beats they stay out of the sim, so replays, seeks and gym reports are unchanged, and a seek onto the end still poses the winner. |
| 2026-10-16 | The lineup belongs to the controller: "Next match" repeats it with a new seed, the player's picks stay pinned and only unpinned slots are drawn from the house stacks (seeded, so the same lineup, rules and seed give the same fight). Quick matchup replaces the old match setup dialog. | A fighter brought in from the gym, the editor or a file dropped out on "Next match". |
| 2026-10-16 | Version numbers belong to the library: per name, monotonic, never reused, even after a delete; parent and origin are recorded separately. | Saving renumbered silently and evolved builds read "v140"; one model lets the editor say exactly what a save will do. |
| 2026-10-16 | V toggles the cinematic view; vision cones moved to E, so every letter has one meaning. | The spec gives V to the cinematic view, and a letter with two meanings is a bug; a test checks that every letter has one. |
| 2026-10-16 | The room protocol is version 2; peers on an older build are refused with "reload". Every guest-side buffer is capped and each sender has a message budget. | New frame fields (stuck ammo, bleed) and messages (minds, gore history, reports) change the wire; a hostile host must not be able to grow a guest's memory without bound. |
| 2026-10-15 | A round is framed by the app, not the sim: the controller holds the sim at tick 0 behind the splash and through "3, 2, 1, FIGHT!", and gives the final kill about 3 s (ultra slow motion, camera, WINNER stamp) before the end card. The beats reach renderer and audio as `MatchSignal`s; a seek drops queued beats and a replay to the end goes straight to the card. | The user saw matches start mid-air behind the splash and the end card cut the best moment short. Keeping the beats out of the sim keeps replays, seeks and gym reports identical. |
| 2026-10-15 | Watch-screen panels float over a full-bleed canvas and report what they cover (`setViewInsets`); the canvas never resizes when a panel opens, closes or is dragged. | Resizing a WebGPU canvas on every drag shows stretched frames and costs a re-layout; framing the camera inside the uncovered part keeps the action in view without that. (SPEC asked for a canvas that resizes live; this replaces it, pending the user's confirmation.) |
| 2026-10-15 | The closing wall is solid: contact damage every tick, a push back in, crushing against walls, pillars and props. Its numbers live in `MATCH_RULES` (`wallContactDamage`, `wallPushKnockback`, `wallCrushDamage`). | Pass 1's wall let fighters stand outside it taking chip damage; a wall you can stand behind is not a wall. In the rules table the rulebook, the Codex and the LLM prompt describe it like every other rule. |
| 2026-10-15 | Acid slows (`HazardRule.slowTicks`, 40 ticks per damage tick); its damage stays for the balance pass. | Knocking someone into acid should be a tactic and standing in it an obvious mistake; the slow does that without guessing at damage numbers the harness has not measured. |
| 2026-10-15 | Floor blood is stored as data (densities, wetness, soot) in the decal target and turned into colour by one gradient in the floor shader (`goreFloor`). | Multiplying colour stamps went grey-black where splats overlapped and could not dry toward maroon; data adds up exactly and one gradient keeps every overlap, shadow and floor red. |
| 2026-10-15 | The strategy text stays the single source of truth; the visual builder writes minimal edits into it. CodeMirror 6 is the code view, loaded as its own chunk. | Both views stay in sync, the player's formatting and undo survive, and validation runs once on one text. CodeMirror brings lint tooltips, completion and hover docs without a hand-made overlay. |
| 2026-10-15 | Rooms trust the host for which match is shown, never for the shape of any message; strategies travel only to the host, as codes, and pass the gate there with source `network`. Peers watch a stream; nobody else's sim runs. | Host-authoritative streaming avoids lockstep drift across browsers; checking every message keeps a hostile peer or host from crashing or confusing anyone; strategies stay private. |
| 2026-10-15 | three.js and the renderer load as their own chunk (dynamic import when the arena mounts). | The main chunk drops from 1.49 MB to 0.4 MB, so the splash and the gym are ready before three.js arrives; the splash's renderer stage now includes that download. |
| 2026-10-15 | Docs describe decisions and the current state: `SPEC.md` (behaviour), `ARCHITECTURE.md` (code), `DECISIONS.md` (this log), `STATUS.md` (rewritten each pass). The append-only build spec is retired. | The build spec grew by appended "must fix" and "user feedback" sections and stopped reading as one current spec. |
| 2026-10-15 | Screen shake only on kills: one short decaying shake per kill, capped. Ordinary hits get local weight (hit-stop on the two fighters, flash, squash, knockback slide, impact ring, HP chip). | Shake on every hit and projectile impact turned into constant rumbling and hid who hit whom. |
| 2026-10-15 | Carnage is the default blood setting (`DEFAULT_VIEW_SETTINGS.blood = 'carnage'`). | User: vicious, comic splatter out of the box is the point of the game. Light and normal stay available. |
| 2026-10-15 | Fog of war for the selected fighter is on by default. | Seeing the pit through one fighter's eyes is how a viewer understands its decisions. |
| 2026-10-15 | Hearing is fuzzy, and a fighter that loses sight of a target loses the target: it keeps only the last seen spot, then searches. | Pass 1 fighters looked omniscient: 360° hearing through walls wrote exact live positions into memory, so anyone in a fight was tracked perfectly behind walls. |
| 2026-10-15 | No three.js shadow maps. Light comes from a TSL compute light field with 2D wall and pillar occlusion that matches the sim's `lightAt`; fighters, weapons, projectiles and gibs cast soft projected quads, one per nearby light. | What players see as shadow must match the sim's shadow rule (stealth depends on it). Projected quads give soft per-light shadows for 16 moving bodies at low cost. |
| 2026-10-15 | Sudden death is a closing wall with a stalemate trigger (15 s without damage), escalation and a hard cap with a judges' decision. | Hiding or getting stuck must never stall a match; every match ends, and a judged ending is announced and reported, never silent. |
| 2026-10-15 | Balance is measured by a harness (`npm run balance`, `docs/BALANCE.md`), not guessed. | The starting table from the samples favoured ranged weapons; only many seeded matches show whether a change helps. |
| 2026-10-15 | Multiplayer uses host-authoritative WebRTC rooms: the host simulates and streams state, peers watch. A small peer-to-peer prototype (Trystero, no backend) comes before any server work. | Lockstep needs identical results on every machine, but `Math.sin` and other float functions can differ between browsers, so a lockstep sim would drift. The prototype answers whether multiplayer is worth more time before anyone builds a server. |
| 2026-10-15 | Evolution uses MAP-Elites style niches (weapon family x preferred range x aggression) with paired seeds and a re-test before a title changes hands. | A single "best so far" converges on one archetype and crowns a new champion every generation by luck. Niches keep the meta open. |
| 2026-10-15 | Ratings come from openskill (Plackett-Luce over FFA placements), updated from every rated match and persisted. Never set by hand. | The samples' ratings plateaued at 1253 because they were set by hand; a real rating system must move with results. |
| 2026-10-15 | Sound is procedural: synthesized with WebAudio at runtime, no audio asset files. | No licensing or download weight, and every cue can vary in pitch and texture so repeats do not sound canned. |
| 2026-10-15 | One gate for strategies: `loadStrategy(input, source)` for every source, returning a branded `ValidStrategy`; only that type compiles into a brain. | Imported files, pasted text, codes, saved versions, house stacks, evolution children and later network peers must all meet the same rules; the type system makes skipping the gate a compile error. |
| 2026-10-15 | The expression language is parsed once into an AST and evaluated by a small interpreter. No `eval`, no `Function`, no loops or recursion. | Strategies come from strangers and LLMs. Without eval they cannot run code; without loops they cannot hang; their cost per think can be computed before the match. |
| 2026-10-15 | One registry (`src/brain/registry.ts`) defines every sensor, place, zone, move term and policy with doc, unit and range. The validator vocabulary, the JSON Schema and the LLM rulebook are generated from it. | Three hand-kept copies would disagree. With one source, the editor, the validator and the LLM all describe the same language. |
| 2026-10-15 | Strategies are behaviours composed from documented primitives (scored behaviours, context-steering move terms, attack and skill policies), not named black-box verbs. | Players and LLMs can invent tactics the designers did not foresee, and the inspector can show exactly why a fighter did something. |
| 2026-10-15 | three.js r186 with `WebGPURenderer` only, TSL node materials and a TSL `RenderPipeline`. No WebGL fallback anywhere. Without WebGPU the arena shows a "WebGPU required" message; the Gym and Room still work. | User: future-proof and less code. One render path means no second set of shaders, no fallback branches and no WebGL-only APIs. |
| 2026-10-15 | React 18 for the UI shell only. The app loop owns the frame; React reads a controller snapshot at about 10 Hz. | React re-rendering in the per-frame path would cost frames with 16 fighters on screen. |
| 2026-10-15 | A Vite + strict TypeScript project that builds to one static page (deployed to GitHub Pages), instead of a hand-edited single HTML file. | The samples were single hand-edited HTML files with broken, unwired systems. Modules, types and tests let parallel builders work safely; the output is still a static page that needs no server. |
| 2026-10-15 | Free-for-all is the default format: 8 fighters on the pit. Squads and duels are options. | The core fantasy is a chaotic brawl where any strategy can win; FFA also gives ratings many placements per match. |
| 2026-10-15 | Deterministic simulation: the sim, brains and strategy code draw randomness only from the seeded, forkable `Rng`. Same config and seed give the same match in the same browser. | Replays, seeking, gym reports and "Watch this match" all rebuild matches from config and seed instead of storing them. |
| 2026-10-15 | The sample prototypes in `docs/sample/` are concept references only. Their code and structure are never ported. | Many of their systems are broken or fake (evolution and ratings do not work, several controls are unwired). Take ideas, build each system properly. |
